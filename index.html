Robot: reúne los mecanismos

Robot.java guarda hardwareMap, telemetría y las instancias compartidas. La base lo crea con new Robot(this); su constructor recibe el OpMode y prepara MultipleTelemetry para Driver Station y Dashboard.

Para agregar un mecanismo, importa su clase, declara un campo y construye la instancia en el constructor, después de preparar hardwareMap y telemetría. En new Intake(this, "intake"), this es Robot y el texto identifica el motor en FTC. El TeleOp y el periódico usan la misma referencia, robot.intake. La práctica muestra los tres cambios completos.

Construir el objeto no programa sus actualizaciones. Además, cualquier dispositivo requerido por Robot puede causar un error en INIT aunque el modo todavía no use ese mecanismo.

RobotOpMode: mantiene todo funcionando

Los modos que escriben extends RobotOpMode heredan robot y el procesamiento común de botones, scheduler y telemetría. El helper button(...) crea un EctoButton y lo registra para que la base lo actualice.

Conserva super.init() antes de usar Robot y super.loop() para mantener ese procesamiento. En el TeleOp de conducción, robot.mecanum.drive(gamepad) va antes de super.loop(). El ciclo siguiente resume qué hace la base en cada etapa; la práctica incluye su código completo.

El ciclo de un OpMode

El robot repite trabajo durante la ejecución. Estas son las etapas que conviene reconocer al leer un TeleOp.

INIT init()
Limpia botones y scheduler, construye Robot y programa una vez los periódicos registrados. Mientras espera START, init_loop() procesa el scheduler.
START start()
Inicia las acciones del modo. En Prueba Intake, aquí se programa la recolección automática.
LOOP loop()
Se repite mientras el modo está activo: el TeleOp lee el manejo y la base actualiza EctoButton, ejecuta el scheduler y publica robot.telemetry.update().
STOP
Termina la ejecución del modo desde FTC.

periodic() crea el comando que actualiza un mecanismo repetidamente. Se procesa en el scheduler; no es un hilo separado. Una espera bloqueante dentro de ese trabajo puede detener las demás actualizaciones.

Cómo se conecta un mecanismo al proyecto

LugarResponsabilidad
Clase del mecanismoDefine hardware, estados, comandos y la aplicación de salidas.
RobotDeclara y construye una instancia compartida.
RobotOpMode.init()Programa su periódico si necesita actualizaciones continuas.
TeleOp o autónomoPrograma acciones desde botones o secuencias.

En intake e indexer, los comandos cambian estados y el periódico escribe potencia. Los comandos declaran recursos para resolver acciones que compiten por el mismo motor. Define estado inicial, final y comportamiento al interrumpirse.

Heredar de EctoMechanism no registra el objeto en Robot ni programa su periódico.

Cómo identificar una conexión faltante

Si existe la clase, revisa su construcción en Robot; si existe el objeto, su periódico; si se actualiza pero sigue apagado, sus comandos; y si falla un botón, su registro y super.loop().

Las prácticas de Intake e Indexer desarrollan estas conexiones.

Del botón al motor

Piensa en esta cadena cuando quieras entender qué hace un control:

  1. ControlEl conductor presiona.
  2. OpModeRelaciona el botón con una acción.
  3. ComandoSolicita el comportamiento.
  4. MecanismoAplica la salida al hardware.

Ejemplo: Y en Prueba Intake

  1. EctoButton detecta que se presionó Y.
  2. Se programa outtake, que pone el intake en REVERSE.
  3. El periódico de Intake convierte ese estado en potencia para el motor.
  4. Al soltar Y, el comando termina y el intake vuelve a ON.

La idea es separar qué queremos que haga el mecanismo de cómo se aplica al motor. Estados como ON, OFF y REVERSE expresan esa intención.

Mecanismos / Chasis

Chasis.

El chasis ya está programado. Usamos la misma base de movimiento para TeleOp y autónomo; para que funcione bien en nuestro robot, hay que revisar su configuración y tunearlo.

La base viene de Pedro Pathing

Nuestra clase EctoMecanum integra el chasis con Pedro Pathing 3. El equipo organiza su uso dentro de Robot y RobotOpMode; Pedro aporta el drivetrain, la localización y el seguimiento de rutas.

El centro es el Follower. Se crea con Constants.create(hardwareMap) y conecta tres piezas:

PinpointLocalizer
Estima la pose del robot —posición X/Y y orientación— usando el Pinpoint y sus pods de odometría.
Mecanum
Aplica las salidas a los cuatro motores del chasis.
Foresight
Calcula las correcciones para seguir una trayectoria o mantener la pose cuando se solicita ese comportamiento.

El conductor y las trayectorias dan órdenes al mismo robot.mecanum.

Programado no significa calibrado para cualquier robot.

Los nombres de hardware, las direcciones, el montaje de los pods y la respuesta al acelerar y frenar deben corresponder a nuestro montaje. Copiar las constantes de otro robot no sustituye el tuning.

Pedro Pathing: el Follower y su configuración

Odometría: dos dead wheels y Pinpoint

Usamos dos dead wheels: ruedas sin motor con encoders, montadas perpendicularmente para medir avance y movimiento lateral. El goBILDA Pinpoint combina sus lecturas con su IMU para estimar posición y orientación; PinpointLocalizer entrega esa pose al follower para autónomo y manejo field-centric. Funcionamiento de Pinpoint.

  1. Dos podsMiden avance y desplazamiento lateral.
  2. PinpointCombina encoders e IMU.
  3. LocalizerEntrega la pose estimada a Pedro.
  4. FollowerUsa la pose para manejo y rutas.

Para que mida bien, revisa contacto y giro libre de las ruedas, conexiones de los pods, direcciones, tipo de pod y offsets reales del montaje en Constants.localizerConfig. Un pod que pierde contacto o un offset incorrecto distorsiona la pose. Tuning de Pinpoint.

Cómo llega al OpMode

  1. El OpMode llama a super.init()

    RobotOpMode limpia botones y scheduler, y construye Robot(this).

  2. Robot construye EctoMecanum

    El chasis queda disponible como robot.mecanum. Su constructor recibe Robot y obtiene el follower mediante Constants.create(robot.hardwareMap).

  3. La base programa su periodic()

    Ese comando actualiza follower.update(), conserva la pose y publica datos y el dibujo de diagnóstico.

  4. El modo da una orden

    El TeleOp llama a drive(gamepad). El autónomo programa un comando de followPath(path).

  5. super.loop() mantiene el procesamiento

    El scheduler ejecuta los comandos y las actualizaciones periódicas. La base también procesa el scheduler mientras espera START, en init_loop().

EctoMecanum no hereda de EctoMechanism: expone su propio periodic(), que la base programa igualmente. En esta arquitectura, ese periódico ya mantiene el follower actualizado. Conserva esa integración al editar un OpMode; no crees un segundo follower ni añadas otra actualización del mismo follower sin revisar el flujo.

En RedCompTeleOp.loop() primero se llama al manejo y después a la base:

Pasar la pose del autónomo al TeleOp

En el TeleOp rojo, usePreviousStartingPose() está comentado y se establece una pose fija. No se está recuperando automáticamente el final del autónomo.

OpModeStorage.autoEndPose es memoria estática del proceso. Además, nuestro periódico la sobrescribe también durante INIT y TeleOp. Para transferir la pose correctamente hay que revisar cuándo se guarda y cuándo se recupera, antes de que INIT la reemplace; no basta con confiar en el nombre de la variable.

El mismo chasis en autónomo

Las clases de pedroPathing/Paths/ describen por dónde pasar y cómo orientar el robot. El OpMode de robotOpModes/Comp/Auto/ decide qué rutas ejecutar y en qué orden.

  1. En init(), conserva super.init() y establece alianza y pose inicial.
  2. Obtén la ruta de su clase de paths.
  3. En start(), programa el comando de seguimiento.
  4. Mantén el scheduler y el periódico activos mediante la base del OpMode.

En start() de un autónomo con RobotOpMode, encadena las rutas del objeto paths preparado por ese modo. Este fragmento propone una secuencia para RedGardenTopPark; el ZIP las programa por separado:

schedule(
    robot.mecanum.followPath(paths.intakeGarden())
        .then(robot.mecanum.followPath(paths.intakeTopFlower()))
        .then(robot.mecanum.followPath(paths.parkFromTop()))
);

.then(...) inicia cada tramo al terminar el anterior. Varias llamadas independientes a schedule(...) compiten por el mismo follower; no forman una secuencia.

line(...) crea un tramo recto; curve(...), una curva con puntos de control. La interpolación define la orientación durante el recorrido. Un valor fraccional de una interpolación por tramos no representa necesariamente segundos.

Una ruta llamada intakeGarden() solo describe movimiento: no enciende el intake. Las acciones de otros mecanismos se programan explícitamente. Guía de autónomos de Pedro.

import com.arcrobotics.ftclib.gamepad.GamepadEx;

import java.util.ArrayList;
import java.util.List;

public abstract class RobotOpMode extends OpMode {
    protected Robot robot;
    private final List<EctoButton> buttons = new ArrayList<>();

    @Override
    public void init() {
        buttons.clear();
        Scheduler.reset();
        robot = new Robot(this);
        schedule(
            robot.mecanum.periodic(),
            robot.intake.periodic()
        );
    }

    protected EctoButton button(GamepadEx gamepad, Button key) {
        EctoButton button = new EctoButton(gamepad, key);
        buttons.add(button);
        return button;
    }

    @Override
    public void init_loop() {
        Scheduler.execute();
    }

    @Override
    public void loop() {
        buttons.forEach(EctoButton::update);
        Scheduler.execute();
        robot.telemetry.update();
    }
}

package org.firstinspires.ftc.teamcode.mechanisms.Intake;

import static com.pedropathing.ivy.commands.Commands.conditional;
import static com.pedropathing.ivy.commands.Commands.infinite;
import static com.pedropathing.ivy.commands.Commands.instant;
import static com.pedropathing.ivy.commands.Commands.waitMs;

import com.acmerobotics.dashboard.config.Config;
import com.pedropathing.ivy.Command;
import com.qualcomm.robotcore.hardware.DcMotorEx;
import com.qualcomm.robotcore.hardware.DcMotorSimple;

import org.firstinspires.ftc.robotcore.external.navigation.CurrentUnit;
import org.firstinspires.ftc.teamcode.core.BaseClasses.EctoMechanism;
import org.firstinspires.ftc.teamcode.robot.Robot;

import com.pedropathing.ivy.behaviors.InterruptedBehavior;
import java.util.function.BooleanSupplier;

@Config
public class Intake extends EctoMechanism {

    private boolean slowMode = false;
    private Mode mode = Mode.OFF;
    public static double fastPower = -1;
    public static double slowPower = -1;
    public static double offPower = 0;
    public static double reversePower = 1;
    public static double shortReverseTimeMs = 150;

    private final DcMotorEx intakeMotor;


    public Intake(Robot robot, String motorId) {
        super(robot);
        intakeMotor = robot.hardwareMap.get(DcMotorEx.class, motorId);
        intakeMotor.setDirection(DcMotorSimple.Direction.REVERSE);
    }

    public Command defaultCommand(){
        return infinite(()-> mode = Mode.ON)
                .setStart(()-> mode = Mode.ON)
                .requiring(intakeMotor)
                .setPriority(-1)
                .setInterruptedBehavior(InterruptedBehavior.SUSPEND);
    }

    public Command outtake(BooleanSupplier held){
        return Command.build()
                .setStart(()-> mode = Mode.REVERSE)
                .setDone(()-> !held.getAsBoolean())
                .setEnd(endCondition -> mode = Mode.ON)
                .requiring(intakeMotor)
                .setPriority(100);
    }

    public Command on() {
        return instant(() -> mode = Mode.ON).requiring(intakeMotor);
    }

    public Command off() {
        return instant(() -> mode = Mode.OFF).requiring(intakeMotor);
    }

    public Command reverse() {
        return instant(() -> mode = Mode.REVERSE).requiring(intakeMotor);
    }

    public Command shortReverse() {
        return reverse().then(waitMs(shortReverseTimeMs)).then(on());
    }

    public Command toggle() {
        return conditional(() -> mode == Mode.OFF, on(), off());
    }

    public void slowDown() {
        slowMode = true;
    }

    public void speedUp() {
        slowMode = false;
    }

    public Command periodic() {
        return infinite(() -> {
            switch (mode) {
                case ON:
                    intakeMotor.setPower(slowMode ? slowPower : fastPower);
                    break;
                case OFF:
                    intakeMotor.setPower(offPower);
                    break;
                case REVERSE:
                    intakeMotor.setPower(reversePower);
                    break;
            }

            telemetry.addData("Intake Current", intakeMotor.getCurrent(CurrentUnit.MILLIAMPS));
            telemetry.addData("Intake Velocity", intakeMotor.getVelocity());
        });
    }

    enum Mode {
        ON,
        OFF,
        REVERSE
    }
}

public abstract class RobotOpMode extends OpMode {

    @Override

        buttons.clear();
        Scheduler.reset();
        robot = new Robot(this);
        schedule(
            robot.mecanum.periodic(),
            robot.intake.periodic(),
            robot.indexer.periodic()

        buttons.add(button);
        return button;

    @Override
    public void init_loop() {
        Scheduler.execute();
    }

    @Override
    public void loop() {
        buttons.forEach(EctoButton::update);

package org.firstinspires.ftc.teamcode.mechanisms.Indexer;

import static com.pedropathing.ivy.commands.Commands.conditional;
import static com.pedropathing.ivy.commands.Commands.infinite;
import static com.pedropathing.ivy.commands.Commands.instant;
import static com.pedropathing.ivy.commands.Commands.waitMs;

import com.pedropathing.ivy.Command;
import com.qualcomm.robotcore.hardware.DcMotorEx;
import com.qualcomm.robotcore.hardware.DcMotorSimple;

import org.firstinspires.ftc.robotcore.external.navigation.CurrentUnit;
import org.firstinspires.ftc.teamcode.core.BaseClasses.EctoMechanism;
import org.firstinspires.ftc.teamcode.robot.Robot;

import java.util.function.BooleanSupplier;

public class Indexer extends EctoMechanism {

    private boolean slowMode = false;

    private Mode mode = Mode.OFF;
    public static double fastPower = -1;
    public static double slowPower = -1;
    public static double offPower = 0;
    public static double reversePower = 1;
    public static double shortReverseTimeMs = 150;
    private final DcMotorEx indexerMotor;
    public Indexer(Robot robot, String motorId) {
        super(robot);
        indexerMotor = robot.hardwareMap.get(DcMotorEx.class, motorId);
        indexerMotor.setDirection(DcMotorSimple.Direction.REVERSE);
    }

    public Command shoot(BooleanSupplier held) {
        return Command.build()
                .setStart(() -> mode = Mode.ON)
                .setDone(() -> !held.getAsBoolean())
                .setEnd(endCondition -> mode = Mode.OFF)
                .requiring(indexerMotor);
    }

    public com.pedropathing.ivy.Command on() {
        return instant(() -> mode = Indexer.Mode.ON).requiring(indexerMotor);
    }

    public com.pedropathing.ivy.Command off() {
        return instant(() -> mode = Indexer.Mode.OFF).requiring(indexerMotor);
    }

    public com.pedropathing.ivy.Command reverse() {
        return instant(() -> mode = Indexer.Mode.REVERSE).requiring(indexerMotor);
    }

    public com.pedropathing.ivy.Command shortReverse() {
        return reverse().then(waitMs(shortReverseTimeMs)).then(on());
    }

    public com.pedropathing.ivy.Command toggle() {
        return conditional(() -> mode == Indexer.Mode.OFF, on(), off());
    }

    public void slowDown() {
        slowMode = true;
    }

    public void speedUp() {
        slowMode = false;
    }

    public Command periodic() {
        return infinite(() -> {
            switch (mode) {
                case ON:
                    indexerMotor.setPower(slowMode ? slowPower : fastPower);
                    break;
                case OFF:
                    indexerMotor.setPower(offPower);
                    break;
                case REVERSE:
                    indexerMotor.setPower(reversePower);
                    break;
            }

            telemetry.addData("Indexer Current", indexerMotor.getCurrent(CurrentUnit.MILLIAMPS));
            telemetry.addData("Indexer Velocity", indexerMotor.getVelocity());
        });
    }
    enum Mode{
        ON,
        OFF,
        REVERSE
    }

}
